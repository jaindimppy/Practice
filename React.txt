        setList(tempList);
        setIsedit(-1);

"What causes a React component to re-render?"
The Answer: A component re-renders under three primary conditions:
Its local State changes via a setter function (e.g., setCount).
Its Props (inputs passed from a parent component) update.
Its Parent component re-renders.



What is the Virtual DOM and how does reconciliation work?"
. When a state changes, React builds a new Virtual DOM tree and runs a fast "diffing" algorithm against the previous one. It calculates the exact difference and surgically updates only that specific changed element in the real browser DOM.



When you declare an object in JavaScript, the variable doesn’t actually hold the data. It holds a memory address pointer (a reference) that points to a location on the heap where the data lives.
Imagine you have a user state tracking an object:

JavaScript
const [user, setUser] = useState({ name: "Jain", age: 40 });
In the browser's RAM, it looks like this:
Memory Address: 0xABCD123
Value at that address: { name: "Jain", age: 40 }
The variable user simply holds the pointer: 0xABCD123.

2. The Direct Mutation Bug (What happens when you do user.name = "Dimple")
If you write:
JavaScript
user.name = "Dimple";
You are going directly to heap address 0xABCD123 and changing the property value from "Jain" to "Dimple".
The crucial problem: The variable user is still holding the exact same memory address pointer: 0xABCD123. The pointer itself did not change.



useState is a built-in React function (called a "Hook") that allows a component to hold and manage its own private, dynamic memory.
When you modify data using the useState updater gateway, React instantly says: "The memory bank has changed! Let me immediately re-execute this component function to redraw the user interface with the fresh data entries." This automatic redraw is called a Re-render.
