What is the role of the CLR (Common Language Runtime) and CoreCLR?
Responsibilities of CLR
JIT Compilation – Converts IL into machine code.
Garbage Collection (GC) – Automatically frees unused memory.
Exception Handling – Manages exceptions.
Memory Management – Allocates and deallocates memory.
Security – Provides runtime security checks.
Thread Management – Manages multithreading.

CoreCLR is same as CLR but is:
Cross-platform (Windows, Linux, macOS)
Faster and more optimized
Designed for cloud, containers, and microservices


What is the middleware pipeline in ASP.NET Core? How do app.Use(), app.Run(), and app.Map() differ?

| Method      | Purpose                     | Calls Next Middleware? | Terminates Pipeline? |

How does Garbage Collector (GC) work?
The Garbage Collector automatically manages memory by identifying objects that are no longer reachable and reclaiming their memory. It uses a generational model (Gen 0, Gen 1, Gen 2) where short-lived objects are collected frequently and reside in Gen0 and If there is not sufficient memory in generation 0 then it will promote the generation o to generation 1.
If space occupied by some generation 0 objects that are not released in a garbage collection run, then these objects get moved to generation 1.
This generation contains short-lived objects and serves as a buffer between short-lived objects and long-lived objects.
When there is no sufficient memory the object from the generation 1 will be promoted to the generation 2.
Generation 2 will contains longest lived object such as static objects, global variables as they remain in the heap memory for the whole process duration.

Why avoid async void except in event handlers?
Writing a normal method- Always use async Task (or async Task<T>).
Writing an event handler-Use async void.
The short explanation is: async void is a "fire-and-forget" mechanism. When you use it, the calling code has no way to track when the method finishes, and more importantly, any exception thrown inside an async void method will crash your entire application.
When an exception is thrown in a standard async Task method, the exception is caught and placed inside the returned Task object. When you await that task, the exception is re-thrown safely, allowing you to catch it with a standard try/catch block.
