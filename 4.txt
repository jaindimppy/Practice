*Explain the structural and architectural difference between a Clustered Index and a Non-Clustered Index. How many clustered indexes can a single table have, and why?
When you create a Clustered Index (usually on your Primary Key ID), the database physically sorts the rows on the hard drive by that ID.
It just contains the keyword and a page number (pointer) telling you where to find the real information. When the database searches a non-clustered index, it finds the match, but it only finds a pointer.
It then has to take an extra step: use that pointer to jump over to the main table to fetch the rest of the row information. 
We have only one clutered index per table because we have only one PK and clustered index created on PK.
